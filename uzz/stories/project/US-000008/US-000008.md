## project/US-000008 — Repair an Incomplete Knowledge Base and Report the Outcome

### User Story

```
AS A Uzzo workflow user
I WANT initialization to be additive and to tell me what it created, skipped and left to fill in
SO THAT I can safely run it on a partially set up knowledge base without losing any of my content
```

#### Status
DONE

#### Dependencies
- project/US-000005
- project/US-000006

#### Technical Context & Constraints
* **Target System**: NetBeans IDE module (`nbm`), Projects view, Output/notification UI.
* **Toolchain / Rules**: Java 21, NetBeans Platform `RELEASE280`, Maven, JUnit 5.

#### Notes
1. Rules mirror `uzzo-init`: never delete, rename, truncate or overwrite an existing file or directory; populate a file only if missing or empty; skip and report everything else.
2. The run is classified as Fresh, Repair or Complete. When Complete, nothing is written.
3. If `uzz` exists as a file, or completing the structure would require modifying existing content, the run stops and reports the conflicting paths.
4. When a knowledge base already exists but is incomplete, the action is offered on the Uzzo Knowledge Base node as "Repair Uzzo Knowledge Base" (the project-level action is only for projects without `uzz`).
5. The outcome report lists Created, Skipped, Placeholders (file and field) and Incomplete items, and suggests the next steps (fill placeholders, then scope, story and code skills).

### Acceptance Criteria

```gherkin
Scenario: Repair a partial knowledge base
  Given "uzz" contains "stories/scope.md" with custom content and lacks "project/overview.md"
  When  the user invokes "Repair Uzzo Knowledge Base" on the Uzzo Knowledge Base node
  Then  "project/overview.md" and the other missing items are created
  And   "stories/scope.md" is unchanged
  And   it is reported as skipped

Scenario: Empty seed file is populated
  Given "project/coding_standard.md" exists but is empty
  When  the user invokes "Repair Uzzo Knowledge Base"
  Then  it is populated from the template

Scenario: Complete knowledge base
  Given the knowledge base has every required directory and file
  When  the user invokes "Repair Uzzo Knowledge Base"
  Then  no file is written
  And   the outcome states that the knowledge base is already complete

Scenario: Outcome report
  Given an initialization or repair has finished
  Then  the user sees the created items, the skipped items, the placeholders still to fill with file and field, and the next steps

Scenario: Conflicting path
  Given "uzz" exists as a regular file
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  nothing is modified
  And   the conflicting path is reported to the user
```

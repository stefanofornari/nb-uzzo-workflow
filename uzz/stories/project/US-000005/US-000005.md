## project/US-000005 — Initialize the Knowledge Base from the Project Context Menu

### User Story

```
AS A Uzzo workflow user
I WANT an "Initialize Uzzo Knowledge Base" action on a Maven project that has no `uzz` folder
SO THAT I can start using the Uzzo workflow on an existing project without leaving the IDE or involving an LLM
```

#### Status
DONE

#### Dependencies
- project/US-000001

#### Technical Context & Constraints
* **Target System**: NetBeans IDE module (`nbm`), Projects view context menu of Maven projects.
* **Toolchain / Rules**: Java 17, NetBeans Platform `RELEASE280`, Maven, JUnit 5; follows `uzz/project/coding_standard.md`.

#### Notes
1. The action is contributed to the Maven project node context menu, because the Uzzo Knowledge Base node does not exist while `uzz` is missing.
2. Initialization is programmatic and deterministic: it reproduces the `uzzo-init` skill (`uzz/skills/uzzo-init/SKILL.md`) without an LLM.
3. Layout created: `uzz/{library,project,skills,stories}`; an empty `.gitkeep` is added to every directory that is still an empty leaf at the end of the run. Once US-000006 seeds articles and skills, only the directories left empty (typically `library/`) keep it.
4. No `.md` file is placed directly under `uzz/`; no story folders or story files are created.
5. The seed articles and workflow skills are provided by the `uzzo-workflow-kb` dependency, see US-000006; this story covers the action, the directory skeleton and the file creation mechanics.
6. File creation runs off the Event Dispatch Thread.
7. Once `uzz` exists, the existing node factory shows the Uzzo Knowledge Base node without restarting the IDE.
8. The action stays enabled when `uzz` exists as a regular file; the run then stops and names the conflicting path (see US-000008).

### Acceptance Criteria

```gherkin
Scenario: Action offered on a project without a knowledge base
  Given a Maven project with no top-level "uzz" folder
  When  the user opens the project's context menu
  Then  an "Initialize Uzzo Knowledge Base" action is offered

Scenario: Action hidden when the knowledge base exists
  Given a Maven project with a top-level "uzz" folder
  When  the user opens the project's context menu
  Then  the "Initialize Uzzo Knowledge Base" action is not enabled

Scenario: Fresh initialization
  Given a Maven project with no top-level "uzz" folder
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  "uzz" is created with the "library", "project", "skills" and "stories" folders
  And   each folder that is empty contains an empty ".gitkeep"
  And   no ".md" file sits directly under "uzz"
  And   no story folder or story file is created
  And   the Uzzo Knowledge Base node appears in the Projects view

Scenario: Creation failure
  Given a Maven project whose directory is not writable
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  an error message names the path that could not be created
  And   no empty "uzz" folder is left behind

Scenario: Conflicting file
  Given a Maven project where "uzz" exists as a regular file
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  nothing is modified
  And   an error message names the conflicting path
```

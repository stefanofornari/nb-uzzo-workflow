## project/US-000006 — Seed the Knowledge Base from the Uzzo Workflow Distribution

### User Story

```
AS A Uzzo workflow user
I WANT the initialized knowledge base to be populated with the workflow skills and seed articles of the uzzo-workflow distribution
SO THAT the project starts with the canonical skills and article templates, always aligned with the Uzzo workflow version I use
```

#### Status
DONE

#### Dependencies
- project/US-000005
- uzzo-workflow: distribution/US-000014

#### Technical Context & Constraints
* **Target System**: NetBeans IDE module (`nbm`), Maven dependency on `uzzo-workflow-kb` (sibling project `stefanofornari/uzzo-workflow`).
* **Toolchain / Rules**: Java 21, NetBeans Platform `RELEASE280`, Maven, JUnit 5.

#### Notes
1. The single source of truth for the seeded content is the `uzzo-workflow-kb` artifact of `uzzo-workflow` (`com.github.stefanofornari:uzzo-workflow-kb`), which ships it under the `uzz/` classpath prefix. The module must not keep its own copy of that content.
2. Only `skills/**` is copied from the dependency, verbatim. Skills installed: `kb/SKILL.md`, `kb/references/user_story.md`, `scope/SKILL.md`, `story/SKILL.md`, `code/SKILL.md`, `uzzo-init/SKILL.md`, `uzzo-init/references/templates.md`.
3. The distribution's `project/` and `stories/` files are not copied: they are specific to another project (and `stories/scope.md` is a different template), so copying them would seed wrong facts. The six articles `project/{overview,coding_standard,development_framework}.md` and `stories/{scope,users,index}.md` are generated from the templates in `skills/uzzo-init/references/templates.md` of the same dependency, keeping bracketed placeholders (see US-000007).
4. `stories/index.md` has no domain sections and no story folders or files are created. Every generated article ends with `### Keywords`.
5. Prerequisite: `uzzo-workflow` `distribution/US-000014` (dependency-free `uzzo-workflow-kb` artifact) is delivered.
6. The module declares `uzzo-workflow-kb` as a regular dependency; it has no transitive dependencies, so the agent libraries (langchain4j, etc.) are not bundled in the `nbm`. `nbm-maven-plugin` packages the jar as an extension, so installation works offline.
7. Files to copy are discovered by resolving a known resource (`/uzz/skills/kb/SKILL.md`) to its location and listing the `uzz/` tree from there (jar entries, or a directory walk when it resolves to a folder, as in tests), since a classpath directory inside a jar cannot be listed directly.
8. If the distribution content cannot be read, the skeleton is still created, the run is reported as incomplete and the module does not invent stub content.
9. Follow-up for `uzzo-workflow`: the stale `project/` and `stories/` files under `src/main/uzz` should be removed or replaced by real seeds; not done here.

### Acceptance Criteria

```gherkin
Scenario: Skills come from the dependency
  Given the uzzo-workflow-kb dependency ships its "uzz/skills" content
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  "uzz/skills" contains the kb, scope, story, code and uzzo-init skill directories
  And   "uzz/skills/kb/references/user_story.md" exists
  And   each copied file is byte-identical to the file in the dependency

Scenario: Articles are generated from the templates
  Given the dependency ships "skills/uzzo-init/references/templates.md"
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  "project/overview.md", "project/coding_standard.md", "project/development_framework.md", "stories/scope.md", "stories/users.md" and "stories/index.md" are created from the templates
  And   each ends with a "### Keywords" section
  And   "stories/index.md" has no domain section
  And   "library" contains an empty ".gitkeep"
  And   no ".gitkeep" is added to a folder that has content

Scenario: Distribution content unavailable
  Given the distribution content cannot be read
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  the skeleton is created
  And   no invented content is written
  And   the outcome reports the knowledge base as incomplete
```

# project/US-000006 — Implementation Notes

Technical notes for [Seed the Knowledge Base from the Uzzo Workflow Distribution](US-000006.md).

1. The content comes from the plain dependency `com.github.stefanofornari:uzzo-workflow-kb`, which has no transitive dependencies. `nbm-maven-plugin` bundles it as `modules/ext/.../uzzo-workflow-kb.jar`; no langchain4j jars are packaged.
2. `KnowledgeBaseContent` (`paths()`, `read(path)`) hides where the content lives. `ClasspathKnowledgeBaseContent` locates the marker resource `uzz/skills/kb/SKILL.md`, then lists its jar (`JarURLConnection`, no cache, closed afterwards) or, when run from a folder, the folder three levels up.
3. Only `skills/**` is copied, byte for byte. The distribution also carries `project/*` and `stories/{scope,users}.md` leftovers that are deliberately ignored.
4. The six articles (`project/{overview,coding_standard,development_framework}.md`, `stories/{scope,users,index}.md`) are generated by `KnowledgeBaseTemplates.extract` from `skills/uzzo-init/references/templates.md`: the fenced block under the heading naming the article.
5. Content problems do not abort: the skeleton is still created and `Result.incomplete()` lists what is missing; the action shows it as a warning. Only I/O failures while writing roll back `uzz`.
6. Paths with empty, `.` or `..` segments are rejected to avoid escaping `uzz`.
7. `.gitkeep` is added last, only to folders still empty (`library`).
8. Known follow-up: the stale `project/` and `stories/` files in `uzzo-workflow/src/main/uzz` should be cleaned up upstream.

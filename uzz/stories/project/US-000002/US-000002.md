## project/US-000002 — Open Knowledge Base Documents in a Dedicated Editor Deck

### User Story

```
AS A Uzzo workflow user
I WANT documents opened from the uzz folder to appear in a dedicated deck on the right of the IDE
SO THAT knowledge base documents stay organised and do not mix with my source-code editors
```

#### Status
DONE

#### Dependencies
- None

#### Technical Context & Constraints
* **Target System**: NetBeans IDE module (`nbm`), window system mode `uzzoKnowledgeBase`.
* **Toolchain / Rules**: Java 17, NetBeans Platform `RELEASE280` (window system, `TopComponent` registry, `FileOwnerQuery`), Maven, JUnit 5.
* **Phase**: Delivered — the module already implements this capability.

### Acceptance Criteria

```gherkin
Scenario: Open a document inside the knowledge base
  Given an open Maven project with a top-level "uzz" folder containing a document
  When  the user opens that document
  Then  its editor is docked into the dedicated "uzzoKnowledgeBase" deck on the right
  And   the editor becomes the active component

Scenario: Open a project source file
  Given an open Maven project with a source file outside the "uzz" folder
  When  the user opens that file
  Then  its editor remains in the central editor deck

Scenario: Open a file in a lookalike folder
  Given a file stored in a folder named "uzz" that is not the project's top-level knowledge base
  When  the user opens that file
  Then  its editor remains in the central editor deck

Scenario: Open a file without a project
  Given a file that is not owned by any NetBeans project
  When  the user opens that file
  Then  its editor remains in the central editor deck

Scenario: Dedicated deck is unavailable
  Given the "uzzoKnowledgeBase" mode cannot be found in the window system
  When  the user opens a document inside the knowledge base
  Then  the editor stays in its current deck and no error interrupts the user

Scenario: Editor re-docks itself after opening
  Given an editor that moves itself back to the central deck shortly after opening
  When  the user opens a document inside the knowledge base
  Then  the hook re-checks after a short delay and docks the editor into the dedicated deck again
```

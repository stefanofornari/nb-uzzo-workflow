## project/US-000007 — Pre-fill Project Facts from the Maven Project

### User Story

```
AS A Uzzo workflow user
I WANT the initialization to propose the project name, version, summary, repository and toolchain from my Maven project
SO THAT the seed articles contain real facts and fewer placeholders to fill in by hand
```

#### Technical Context & Constraints
* **Target System**: NetBeans IDE module (`nbm`), Maven project model, Swing dialog.
* **Toolchain / Rules**: Java 17, NetBeans Platform `RELEASE280`, Maven, JUnit 5.

#### Notes
1. Before writing, a confirmation dialog shows the values read from the project `pom.xml` and lets the user edit or clear them: name, version, description (summary), SCM/repository URL, Java release.
2. Only facts present in the pom are proposed; nothing is guessed. Absent values stay as bracketed placeholders (`[PROJECT NAME]`, `[VERSION]`, ...), as required by `uzzo-init`.
3. Edited values replace placeholders in `project/overview.md`, `project/development_framework.md` (language/build tool, build and test commands only when derivable, e.g. `mvn clean install`) and `stories/scope.md` (name, version).
4. Placeholders are replaced in the content copied from the `uzzo-workflow` dependency (US-000006); the dependency files themselves are never modified.
5. Cancelling the dialog aborts initialization without creating anything.

### Acceptance Criteria

```gherkin
Scenario: Facts proposed from the pom
  Given a Maven project whose pom defines name, version, description and an SCM URL
  When  the user invokes "Initialize Uzzo Knowledge Base"
  Then  a dialog shows these values pre-filled and editable

Scenario: Confirmed values are written
  Given the dialog shows pre-filled values
  When  the user edits the name and confirms
  Then  "project/overview.md" and "stories/scope.md" contain the edited name and the pom version
  And   no placeholder remains for the supplied values

Scenario: Missing facts stay placeholders
  Given a Maven project whose pom has no description and no SCM URL
  When  the user confirms the dialog leaving those fields empty
  Then  the summary and repository fields keep their bracketed placeholders

Scenario: Dialog cancelled
  Given the dialog is displayed
  When  the user cancels it
  Then  no "uzz" folder is created
```
